# Data Model: Phase 1 — Deterministic Whitebox Core Loop

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

Units: **su** = simulation unit (block width = 1000 su), **ticks** = 1/60 s, **‰** = per-mille
(1000 = 1.0), **uint32** = integer in [0, 2^32). All sim values are safe integers (Principle I).
Formulas are those of PRD §3–§4 and are not repeated here.

### 1.3 Structural constants (fixed, not in `TuningValues`)

`TICK_RATE = 60`, `BLOCK_WIDTH = 1000` su, `MAX_TICKS_PER_FRAME = 5`, `SIN_LUT_SIZE = 4096`.
These are exported from `tuning.ts` but cannot be overridden (see research R10).

**Validation**: `createSim` throws `SimConfigError` unless every field is present, is a safe
integer, and is within its bounds. `isDefaultTuning(t)` returns true only when every field equals
`DEFAULT_TUNING`.

## 3. SimState

A single plain object of integers plus one integer array. Enumerations are stored as integer codes.
`getState()` returns this object read-only and live (research R12).

| Field | Unit / codes | Meaning |
| --- | --- | --- |
| `typeCode` | 0 res, 1 com, 2 off, 3 lux | From config |
| `modeCode` | 0 city, 1 quick | From config |
| `assist` | 0 / 1 | From config (FR-048) |
| `seed` | uint32 | From config |
| `tick` | ticks | Number of completed steps. The step in progress processes `tick` after incrementing |
| `rngState` | uint32 | mulberry32 state |
| `phase` | 0 spawnDelay, 1 swinging, 2 falling, 3 ended | Run phase |
| `phaseTimer` | ticks | Remaining spawn-delay ticks |
| `result` | 0 none, 1 completed, 2 built, 3 gameOver | Run result (FR-044) |
| `finalScore` | population | 0 until `result ≠ 0` |
| `strikes` | count | 0 … `LIVES` |
| `score` | population | Sum of floor population so far (no bonus) |
| `floors` | count | N |
| `restX` | su[] | Length N + 1; `restX[0] = 0` is the foundation |
| `leanSum` | su | Σ `restX[1..N]` |
| `lean` | su | `div(leanSum, N)`, or 0 when N = 0 |
| `isRoof` | 0 / 1 | Current block is the roof |
| `roofCommitted` | 0 / 1 | Early roof was placed; later spawns are roofs |
| `craneCenterX` | su | `restX[N]` at spawn |
| `cranePhase` | uint32 | Crane phase accumulator |
| `craneIncrement` | uint32 / tick | Set at spawn |
| `craneSpeed` | ‰ | Set at spawn |
| `craneX` | su | Hook X after this tick |
| `releaseX` | su | Frozen X of the falling block |
| `releaseTick` | ticks | Tick the drop was applied |
| `landingTick` | ticks | `releaseTick + DROP_FALL_TICKS` |
| `combo` | count | Consecutive Perfects |
| `comboMult` | ‰ | Current combo multiplier |
| `goodCount` | count | Good landings this run (never decreases) |
| `sensitivity` | ‰ | Current sensitivity |
| `stabilizer` | ‰ | Current stabilizer |
| `swayPhase` | uint32 | Sway phase accumulator; starts at 0 when floor 1 is placed |
| `swayIncrement` | uint32 / tick | From `swayPeriodTicks` |
| `swayAmp` | su | Current (smoothed) amplitude |
| `swayTarget` | su | Target amplitude |
| `swayS` | su | Current top-floor displacement S |
| `pendingInput` | 0 none, 1 drop, 2 roof | Queued by `requestDrop` / `requestRoof` |
| `lastOffset` | su (signed) | d of the last landing |
| `lastTier` | 0 none, 1 perfect, 2 good, 3 miss | Tier of the last landing |

### Hash order

`hashState` feeds fields in exactly the order of the table above (`typeCode` … `lastTier`).
`restX` is written as its length followed by its elements. The encoding is described in
research R11. Adding, removing or reordering a field changes every hash, and therefore requires
regenerating the golden fixtures and bumping `SIM_VERSION`.

### Invariants (tested)

- Every field and every `restX[i]` satisfies `Number.isSafeInteger` (SC-002).
- `0 ≤ strikes ≤ LIVES`; `result = 3` ⇔ `strikes = LIVES`.
- `craneSpeed ≤ CRANE_SPEED_CAP`, `sensitivity ≤ SENSITIVITY_CAP`, `|swayAmp| ≤ SWAY_AMP_CAP`,
  `comboMult ≤ COMBO_CAP`, `stabilizer ≥ STABILIZER_FLOOR` (SC-005).
- `restX.length = floors + 1`; `restX[0] = 0`.
- `result ≠ 0` ⇔ `phase = 3`. After that, no field changes (FR-045).
- `modeCode = 1` ⇒ `isRoof = 0` and `result ∈ {0, 3}`.

## 4. Tick pipeline

Order of operations inside one `step()` (research R6):

```text
step():
  clear reused event array
  if result ≠ 0: return events (empty)                         # FR-045
  tick += 1
  apply pendingInput:
    drop  (phase = swinging): releaseX = craneX, releaseTick = tick,
                              landingTick = tick + DROP_FALL_TICKS, phase = falling,
                              log {tick, 'drop'}, emit release
    roof  (phase = swinging, eligible): isRoof = 1, roofCommitted = 1, log {tick, 'roof'}
    pendingInput = 0
  if floors ≥ 1: advance swayPhase; smooth swayAmp toward swayTarget; compute swayS
  switch phase:
    spawnDelay: if phaseTimer = 0 → spawn (below) else phaseTimer -= 1
                (after decrementing, spawn in the same tick when it reaches 0)
    swinging:   cranePhase += craneIncrement (>>> 0); craneX = craneCenterX + crane offset
    falling:    if tick = landingTick → evaluate landing (below)
  return events

spawn:
  craneCenterX = restX[N]; cranePhase = next uint32 from mulberry32
  craneSpeed = min(CAP, 1000 + PER_FLOOR × N); craneIncrement = div(div(2^32, period) × craneSpeed, 1000)
  isRoof = (city and (N ≥ targetFloors or roofCommitted))
  craneX = craneCenterX + crane offset; phase = swinging
  emit spawn {isRoof}; if city and not isRoof and N ≥ minRoofFloors: emit roofAvailable

evaluate landing:
  d = releaseX − (restX[N] + swayS); classify |d| by PERFECT_MAX / GOOD_MAX
  Miss:    strikes += 1, combo = 0, lastTier = miss, emit miss, emit comboChanged if needed
           strikes = LIVES → end(gameOver) else spawnDelay
  roof + Perfect/Good: end(completed if N ≥ targetFloors else built)
  Perfect: combo += 1, comboMult = min(CAP, 1000 + STEP × combo), pop = div(perfectPop × comboMult, 1000),
           restX.push(restX[N]), stabilizer = max(FLOOR, div(stabilizer × STEP, 1000))
  Good:    combo = 0, comboMult = 1000, pop = goodPop, restX.push(restX[N] + d),
           stabilizer = 1000, goodCount += 1
  Perfect/Good (non-roof): N += 1, score += pop, update leanSum/lean,
           if N = 1: swayPhase = 0; recompute swayTarget (PRD §4.3);
           emit land, emit comboChanged; phaseTimer = SPAWN_DELAY_TICKS; phase = spawnDelay

end(r):
  result = r; finalScore = score + (r = completed ? div(score × COMPLETION_BONUS, 1000) : 0)
  phase = ended; emit finished {result, score: finalScore} or gameOver {score: finalScore}
```

A spawn delay of `SPAWN_DELAY_TICKS` means the next block spawns exactly that many ticks after
the landing tick.

## 5. State transitions

```text
          createSim
              │  (phase = spawnDelay, phaseTimer = 0)
              ▼
     ┌──► spawnDelay ──(timer reaches 0)──► swinging ──(drop applied)──► falling
     │        ▲                               │  ▲                          │
     │        │                          roof applied                      │ tick = landingTick
     │        │                          (isRoof = 1; stays swinging)      ▼
     │        └──── Perfect/Good floor, or Miss with strikes < LIVES ◄── evaluate
     │                                                                     │
     └──────────────────── (roof Miss respawns a roof) ──────────────────┘ │
                                                                           ▼
                            ended  (roof Perfect/Good → completed | built;
                                    Miss with strikes = LIVES → gameOver)
```

## 6. Input log and events

- **InputEvent**: `{ tick: number; type: 'drop' | 'roof' }`. `tick` is the tick on which the input
  was **applied**. The log is strictly increasing in `tick`; there is at most one input per tick.
- **SimEvent**: PRD §8.3 union, with two extensions:
  - `land` gains `roof: boolean`; a roof landing reports `floor = N` and `pop = 0`.
  - `finished` and `gameOver` gain `floors: number`.

---

## 7. RunResult

Derived from the final state: `{ result: 'completed' | 'built' | 'gameOver', score: finalScore,
floors }`. It is present only when `state.result ≠ 0`.

## 8. RunExport / GoldenFixture

A JSON document, specified in [contracts/run-export.schema.json](./contracts/run-export.schema.json):

| Field | Meaning |
| --- | --- |
| `format` | Always `"skyline-stacker/run"` |
| `exportVersion` | `1` |
| `simVersion` | `SIM_VERSION` of the sim that played it |
| `tuningVersion` | `TUNING_VERSION` at play time |
| `tuningOverridden` | `!isDefaultTuning(config.tuning)` (FR-039) |
| `config` | Full `SimConfig`, including the complete `tuning` (FR-041, FR-049) |
| `inputLog` | `InputEvent[]` |
| `result` | `RunResult` |
| `hash` | uint32 final `hashState` |

A **GoldenFixture** is a RunExport with `tuningOverridden = false`,
`tuningVersion = TUNING_VERSION`, and `config.tuning` deep-equal to `DEFAULT_TUNING` (FR-043).

## 9. Presentation-only models (`apps/web`, not hashed)

- **RenderSnapshot**: preallocated `prev` / `curr` pair holding crane X, sway S, fall progress
  (ticks since release) and camera target Y, used for `alpha` interpolation (FR-029).
- **FloorPool**: fixed pool of tinted block images, sized to the most floors that fit in the
  viewport plus a margin. Only floors in view are assigned an image (FR-031).
- **PerfCapture**: preallocated `Float64Array` of frame times for 60 s (research R16).
